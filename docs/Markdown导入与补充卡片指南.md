# Markdown 导入与补充卡片指南

这份指南介绍怎样把自己的课程资料整理成闪卡、导入手机，并在以后只补充新内容。应用读取 UTF-8 Markdown；普通文章不会自动变成问答卡，需要先把知识点拆成能主动回忆的问题和答案。

可以先从[可直接导入的补充卡片模板](../samples/markdown/补充卡片模板.md)开始。请在应用里选择这个独立模板文件；本指南是阅读说明，不是导入文件。模板包含 3 条笔记：2 条普通问答卡，以及 1 条含两个不同编号挖空的笔记；导入预览预期为 **3 条笔记、4 张卡**。

## 文件结构

需要指定科目、牌组或标签时，在 Markdown 文件开头添加一组 YAML 元数据。示例：

````markdown
---
subject: "408"
deck: "数据结构/查找"
tags: ["二分查找", "基础"]
---

## 二分查找的前提和时间复杂度

### 正面
在可随机访问的数组上，二分查找要求数据满足什么条件？最坏时间复杂度是多少？

### 背面
数组元素必须有序；每一步排除约一半候选项，最坏时间复杂度为 O(log n)。

## 双编号挖空示例

### 正面
二分查找在可随机访问的数组上要求元素{{c1::有序}}；最坏时间复杂度为{{c2::O(log n)}}。

### 背面
每一步比较中间项并保留可能包含目标的一半区间。

```text
## 代码围栏中的双井号不会开始新笔记
```
````

### 元数据

| 字段 | 写法和规则 | 示例 |
| --- | --- | --- |
| `subject` | 必须是字符串；数字科目也要加引号 | `subject: "408"` |
| `deck` | 必须是字符串；用 `/` 表示牌组层级 | `deck: "数据结构/查找"` |
| `tags` | 可选的字符串列表；各项都用引号更稳妥 | `tags: ["二分查找", "基础"]` |

如果要指定 YAML 元数据，文件第一行必须是 `---`，下一行开始写元数据，再用一行 `---` 结束元数据。整份文件共用这一组科目、牌组和标签。第二组 `---` 不会切换到另一个科目；不同科目或牌组请另存为不同文件。不提供元数据时，内容会放入“未分类 / 收件箱”。

### 笔记与卡片

- 每条笔记以 `##` 开始，后面写标题。
- 每条笔记需要且只能有一个 `### 正面`，之后有一个 `### 背面`。`### Front` 等英文标题不识别。
- 正面必须有内容；普通问答卡的背面也必须有内容。填空卡也保留 `### 背面`，可以写解释、记忆线索或例子。
- 没有填空标记时，一条笔记生成一张普通卡。正面里有挖空标记时，按不同编号生成填空卡。
- 正文里的 `##` 会被识别为下一条笔记标题。需要展示 Markdown 标题或类似代码时，把内容放进围栏代码块。

### 挖空语法

在正面写 `{{c1::答案}}`，或带提示写成 `{{c1::答案::提示}}`。例如：

````markdown
### 正面
栈按{{c1::后进先出}}原则工作；队列按{{c2::先进先出}}原则工作。
````

同一个编号可以出现多次，这些空会在同一张卡上一同隐藏；不同编号会生成不同卡，并分别安排复习。例如上例生成 2 张填空卡。答案应该完整、简短，提示只用于需要的记忆线索。

同一条笔记里的其他填空卡，在其中一张被评分后会延至次日本地零点；如果想让两个知识点独立复习，应分成两条笔记。

## 从课程资料整理卡片

不要把整篇课文直接复制进文件然后期待应用自动拆卡。先将资料整理成一个个可核对的提示：

1. 一个问题聚焦一个定义、条件、步骤、对比或易错点。
2. 正面只放问题或需要回忆的线索；答案放在背面，保持准确、精炼。
3. 对适合默写的关键词或公式，可用填空。一个编号代表一张卡，同编号可以包含同一答案中的多个位置。
4. 保留资料中的范围和限定条件。不要把“通常”“在某条件下”等删掉而改变结论。
5. 只有需要分层管理时才在 `deck` 中加路径，例如 `数据结构/查找`；不要把科目重复写进牌组名。
6. 公式按普通文本显示，不会排版 LaTeX。复杂公式请用清楚的文本或分步描述，避免依赖图片或公式渲染。

想让 AI 帮忙整理时，可以把教材段落连同下面的要求一起提供；导入前仍应逐条核对：

> 只根据我提供的资料，把内容拆成可主动回忆的闪卡。不得补充资料之外的事实、例子或推论；不确定处标记“需核对”，不要猜。优先保留条件、例外和术语。按本指南的 Markdown 格式输出，普通题写成问答，适合记忆关键词时才使用 `{{c1::答案}}` 填空。输出前检查每条笔记只有一个 `### 正面` 和一个 `### 背面`，正反面内容非空；不要生成元数据之外的额外分隔线。

## 导入到手机

1. 把 `.md` 文件传到手机本地，例如 `Downloads` 文件夹。整理文件不需要联网；请确认完整扩展名是 `.md`，不是 `.md.txt`。
2. 打开应用，进入“设置” → “选择 Markdown 文件”。在系统文件选择器中找到并选择 `.md` 文件；不要选择 ZIP 备份文件。
3. 检查导入预览中的有效笔记数、卡片数、重复项和错误行。取消勾选不想导入的笔记，再点“导入所选”。
4. 返回“牌组”确认笔记和牌组路径；到“今日”开始复习新卡。

单个 Markdown 文件最大 8 MB。预览会列出可导入、重复和有格式问题的笔记。完全重复的笔记不会再次新增；有错误的笔记不会作为有效项导入。导入笔记数和生成卡片数可能不同，尤其是一条笔记包含多个填空编号时。

新卡不会一次全部出现在“今日”。每日新卡上限默认 20 张，可以在设置中调整；剩余新卡会之后逐步安排。

## 如何持续补充

你可以把新笔记追加到原 Markdown 文件，也可以创建单独的增量文件。导入器按科目、牌组、卡片类型、正面和背面识别完全重复项，并会规范化首尾空白和 Unicode。完全相同的内容会跳过，不改变原有学习进度。

只改标题或标签不会创建新笔记，也不会更新已有笔记的标题或标签。若要更正已有内容，建议在“牌组”中直接编辑对应笔记；若改变问答正文或科目/牌组路径，导入器会新增一条笔记，原笔记和进度仍保留，新笔记从头开始安排复习。编辑挖空时尽量保留原有编号：普通卡仍为普通卡，填空卡编号不变时原卡调度会保留；新增编号会新建卡并从头学习。删除或改动编号，以及在普通卡和填空卡之间转换，会移除不再对应的旧卡及其历史，新增卡从头学习。导入是追加操作，不会替换已有牌组内容。

定期保留一份 Markdown 源文件，按主题或增量日期命名，例如 `408-查找-补充.md`。需要回滚整份应用数据时才使用 ZIP 恢复：恢复会完整替换当前数据，不适合作为导入新卡的方式。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 元数据解析报错或科目异常 | 给科目加引号，例如写 `subject: "408"`，不要写未加引号的 YAML 数字 `408`。确认 `deck` 是字符串，`tags` 是字符串列表。 |
| 笔记提示缺少正面或背面 | 检查拼写和标题层级：必须是 `### 正面`、`### 背面`，两者均保留；普通问答的正面与背面不能留空。 |
| 一条笔记被拆成多条 | 检查正文是否有未放入代码围栏的 `##`。它会开始下一条笔记。 |
| 双井号代码也被当成标题 | 确认代码前后有成对且闭合的三反引号围栏。 |
| 文件无法读取或字符乱码 | 将文件保存为 UTF-8 无 BOM。文件带 BOM 时，首行 YAML 分隔符可能无法识别，笔记会落入默认牌组。文件大小需小于或等于 8 MB，并检查完整扩展名是 `.md` 而非 `.md.txt`。 |
| 预览说重复，但我改了标题或标签 | 标题和标签不参与重复识别。要修改原笔记请在“牌组”中编辑；即使只修改正文再导入，也会新增笔记并保留旧笔记。 |
| 选择器里找不到文件 | 确认文件扩展名为 `.md`，已传到手机可访问的本地目录，再从系统文件选择器中定位。 |
| 选到 ZIP 后担心会新增卡片 | ZIP 是完整备份恢复格式，不是 Markdown 导入格式。恢复会替换当前数据；返回取消，不要用 ZIP 代替 `.md` 导入。 |

如需语法示例，可参考 [`samples/markdown/`](../samples/markdown/)；导入预览中的笔记与卡片数量是最终确认本次内容的依据。
